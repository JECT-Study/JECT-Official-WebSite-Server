# GitHub Pull Request 생성 Workflow

이 워크플로우는 현재 작업 내용을 바탕으로 적절한 브랜치를 확인하거나 생성하고, 기본적으로 `dev` 브랜치를 대상으로 PR을 생성합니다.

> **Language Rule**: 생성되는 PR의 제목과 내용은 **한국어**로 작성해야 합니다. (개발 용어 및 키워드는 원문 유지 가능)

## 1. 브랜치 상태 확인 및 생성

현재 작업 중인 브랜치를 확인합니다.

### Case A: `dev` 또는 `main` 브랜치인 경우
직접 커밋이 금지된 브랜치이거나 작업 브랜치가 아닌 경우, 새로운 브랜치를 생성합니다.
1. 작업 내용에 적합한 브랜치명 결정 (`feat/{issue-number}-{english-kebab-case}`, `fix/{issue-number}-{english-kebab-case}`)
2. 브랜치 생성 및 이동: `git checkout -b <new-branch-name>`

### Case B: 이미 작업 브랜치인 경우
현재 브랜치를 그대로 사용합니다.

## 2. 변경사항 커밋 및 푸시

1. 모든 변경사항이 커밋되었는지 확인합니다. (미커밋 시 커밋 요청)
2. 원격 저장소로 브랜치를 푸시합니다.

```bash
git push origin HEAD
```

## 3. Pull Request 본문 작성 및 생성

GitHub CLI를 사용하여 PR을 생성합니다. **PR의 가독성과 정보 전달을 위해 다음 내용을 반드시 포함하여 작성합니다.**

- 기본 base는 `dev`를 사용합니다.
- 아직 병합되지 않은 선행 PR에 의존하면 선행 작업 브랜치를 임시 base로 사용할 수 있습니다.
- 임시 base를 사용하면 PR 본문에 선행 PR 링크와 의존 이유를 작성합니다.
- 선행 PR이 병합되면 base를 `dev`로 변경하고 최신 `dev`를 반영한 뒤 중복 커밋과 변경을 확인합니다.

1. **관련 이슈/PR 링크**: 작업과 관련된 Issue나 다른 PR이 있다면 링크를 포함합니다. (예: `Closes #123`, `Relates to #456`)
    * 브랜치 이름(예: `feat/123-add-member-api`)에서 이슈 번호를 유추하거나, 대화 컨텍스트에서 확인합니다.
2. **작업 내용 상세**: 변경 사항을 상세히 설명하여 리뷰어가 쉽게 이해할 수 있도록 합니다.
    * **변경 목적**: 왜 이 작업을 했는지
    * **구현 상세**: 주요 변경 사항과 로직 설명
    * **검증 결과**: 실행한 테스트와 확인 결과
    * **별도 확인 사항**: migration, API contract, 배포 설정 변경

**프로젝트 PR 템플릿 (`.github/PULL_REQUEST_TEMPLATE.md`) 기반 작성 가이드:**
```markdown
## #️⃣연관된 이슈

close #<Issue_ID>

## 📝 작업 내용

- **<주요 기능/변경점>**
  - 상세 설명 1
  - 상세 설명 2

## 🙏 리뷰 요구사항 (선택)

- 리뷰해주었으면 하는 부분 등 (없으면 해당 섹션 생략 가능)
```

```bash
# 본문은 위 가이드를 따라 상세히 작성합니다.
gh pr create --base <base-branch> --title "PR 제목" --body "작성된 PR 본문"
```

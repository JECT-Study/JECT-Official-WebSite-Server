# GitHub Issue 생성 Workflow

이 워크플로우는 현재 진행 중인 작업의 컨텍스트를 보존하여 추후 작업을 위해 GitHub Issue를 생성하거나, 새로운 이슈를 등록할 때 사용합니다.

> **Language Rule**: 생성되는 모든 이슈의 제목과 내용은 **한국어**로 작성해야 합니다. (개발 용어 및 키워드는 원문 유지 가능)

## 1. 이슈 내용 수집 및 작성

### Case A: 사용자가 구체적인 내용을 제공한 경우
사용자가 제공한 내용에 집중하여 이슈를 작성합니다.

### Case B: 별도 내용 없이 생성을 요청한 경우 (컨텍스트 보존)
현재 세션의 대화 내용을 분석하여 프로젝트의 `.github/ISSUE_TEMPLATE/` 템플릿(`feature_request.md` 또는 `bug_report.md` 등) 중 적합한 양식을 선택하여 `Markdown` 형식으로 작성합니다. 해결 방안은 제외하고 문제 상황 자체에 집중합니다.

**[Feature Request] 템플릿 (`feature_request.md`) 사용 시:**
1.  **## 📃 요약**: 현재 작업의 흐름, 제안하는 기능의 목적, 해결해야 할 구체적인 문제 등
2.  **## 📎 참고 자료 (선택)**: 관련 파일 전체 경로, 기대 결과, 제약 사항 및 특이점 등

**[Bug Report] 템플릿 (`bug_report.md`) 사용 시:**
1.  **## 버그 설명**: 현재 작업의 흐름과 이슈가 발생한 상황 설명
2.  **## 버그 발생 상황**: 버그가 발생한 과정, 관련 파일, 에러 메시지
3.  **## 예상 결과**: 성공 시 달성해야 할 목표 및 정상 상태
4.  **## 참고할만한 자료(선택)**: 제약 사항, 특이점 파악 등

## 2. 사용자 확인

작성된 이슈 제목과 내용을 사용자에게 제시하고 수정할 부분이 있는지 확인합니다.

## 3. 이슈 생성

사용자가 내용을 승인하면, 다음 명령어를 사용하여 이슈를 생성합니다. (GitHub CLI `gh` 사용 권장)

```bash
# 예시 (실제 작성된 제목과 내용으로 대체 필요)
gh issue create --title "이슈 제목" --body "작성된 이슈 본문"
```

> **Note**: `gh` CLI가 설치되어 있지 않은 경우, 브라우저에서 생성할 수 있도록 작성된 본문을 제공합니다.

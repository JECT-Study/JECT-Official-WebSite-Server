# 에이전트 활용 프롬프트 컨벤션

이 문서는 사용자의 의도를 에이전트가 정확히 파악하여 관련 스킬을 자동으로 트리거할 수 있게 돕는 가이드입니다.

## 1. 페이즈별 프롬프트 추천

### Phase 1: 작업 시작 (Issue & Branch)
사용자가 새로운 과제를 던질 때 사용하는 프롬프트입니다.
- **Intent**: 새로운 기능을 만들거나 버그를 수정하고 싶음
- **Recommended Prompt**:
  - "새로운 기능 [기능명]에 대해 이슈 생성하고 개발 시작해줘."
  - "[기능명] 작업할 거야. 이슈 만들고 브랜치 따줘."
- **Triggered Skill**: `github-issue-create`, `github-issue-pick-for-working`

### Phase 2: 개발 및 중간 확인
구현 중간에 검증이 필요할 때 사용합니다.
- **Intent**: 현재까지 작성한 코드가 정상인지 확인하고 싶음
- **Recommended Prompt**:
  - "지금까지 한 거 검증해줘."
  - "컴파일 되는지 확인해줘."
- **Triggered Skill**: `verify-java-essential`

### Phase 3: 마무리 및 PR (Verify & PR)
작업을 완전히 끝내고 코드 리뷰를 요청할 때 사용합니다.
- **Intent**: 모든 검증을 마치고 PR을 올리고 싶음
- **Recommended Prompt**:
  - "작업 완료했어. 전체 검증하고 PR 올려줘."
  - "다 됐으니까 테스트 돌려보고 PR 생성해줘."
- **Triggered Skill**: `verify-implementation`, `github-pr`

---

## 2. 에이전트의 스킬 자동 매핑 원칙

사용자가 명시적으로 스킬명을 부르지 않더라도, 에이전트는 다음 키워드를 통해 의도를 파악합니다:

| 키워드 | 매핑 의도 | 실행 스킬 |
|--------|----------|----------|
| "이슈", "시작하자" | 작업 생성 및 시작 | `github-issue-create` |
| "검증", "체크", "확인" | 코드 품질 확인 | `verify-implementation` |
| "PR", "올려줘", "끝났어" | 작업 제출 | `github-pr` |

## 3. 팁
- **동시 요청**: "이슈 만들고 바로 구현 시작해"처럼 여러 단계를 묶어서 명령할 수 있습니다.
- **세부 지정**: "Essential 검증만 해줘"처럼 특정 수준의 검증만 요청할 수도 있습니다.
